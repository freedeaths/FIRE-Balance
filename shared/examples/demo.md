# FIRE Balance 1 小时入门培训（含预习材料）

这份文档面向“完全零基础”的听众：不了解本 App，也没有系统的理财/保险/投资知识。目标是在 1 小时内让大家：

1. 能把一个计划从 Stage 1 → Stage 2 → Stage 3 跑通，了解每个阶段的内容；
2. 能读懂结果里的“可行/不可行”与“风险”是什么意思；
3. 明白最常见的 3 种改进方向（让计划更稳、更早或更宽裕）。

> 说明：这是工具教学材料，不构成投资/税务/法律建议。

---

## 文件说明（培训用的 2 个案例）

把 `shared/examples/` 目录下的 3 个文件发给听众即可：

- `fire-plan-demo-s.json`：**“很简化但会失败”**的例子。用来解释为什么“只看 4% 规则”会误导。
- `fire-plan-demo-d.json`：**“更接近真实生活”**的例子。用来演示怎么调整把它变成“可行且更稳”的计划。
- `https://fire.freedeaths.com`: 计算工具，有些人不一定能访问得了，电脑上能访问的概率比较大，不行可以几个人一起看，最好不要用微信/360之类的浏览器访问，能用 edge, chrome, safari 访问最好。

导入方式（听众端）：

1. 打开 App
2. 点击“加载财务计划/Load Your Financial Plan”
3. 选择 `fire-plan-demo-*.json`

## 预习材料（建议 15–20 分钟）

### 你只需要掌握的 10 个概念（大白话版）

1. **净资产**：你现在“真有多少钱”，= 资产 − 负债。App 里默认把它当作已经是“税后可用”的金额，动产不动产理论上都可以算进来，算不算进来其实也随你，不算进来，相当于你保守了，算进来，相当于你激进了。
2. **现金流**：每年收入 − 每年支出。正数叫“结余/储蓄”，负数叫“入不敷出”，不是一个“一票否权”项，但也是一个财务数据健康与否的重要指标。
3. **通胀**：钱会慢慢变“不值钱”。App 用“通胀率”把未来的支出/收入做折算，其中 CPI 是通胀率最主要的表现，所以可以近似用 CPI 作为通胀率。你可以不用关心不同的 CPI 指标。
4. **投资组合**：把钱分在不同篮子里（股票/债券/储蓄/现金）。每个篮子有“预期收益”和“波动/风险”。
5. **年化收益**：投资一年大概赚多少（平均）。注意：平均不等于每年都一样。
6. **安全垫（Safety Buffer）**：你账户里需要留一段“可随时动用的缓冲”，避免遇到坏年份就被迫在最低点卖资产。
7. **桥接期（Bridge）**：从你“计划 FIRE 的年龄”到“法定退休开始领养老金”之间的那段空窗期。
8. **生命周期分段（Phase 1–4）**：把人生粗分成四段，用来更容易管理“哪个阶段有哪些收入/支出”。
9. **Monte Carlo（蒙特卡洛）**：把“收益波动、收入波动、黑天鹅”随机抽样跑很多次，看看你的计划在不同世界线里有多稳。
10. **黄灯 / 红灯**：
   - 黄灯：没破产，但出现过至少一个净资产低于安全阈值的年份（紧绷、抗风险弱）
   - 红灯：出现过至少一个净资产 < 0 的年份（破产/负债滚大）
11. **安全阈值**：在有持续收入的时候，它可能是一个固定值，假想一种就是万一突然失业，我可以保证如果 6 个月还没找到工作的情况下我还有钱用。但对于没有持续收入的时候，它可能是一个动态值，在你刚退休的的早期，它需要的更多，然后慢慢变少。
12. **4% 规则**：简单理解就是假设你的投资组合的年化收益是 7%，通胀是 3%，你每年可以提取 4% 的资产作为生活费足够覆盖你一年的支出，而不需要动本金，那就是一种安全的提前退休状态。

### 自己体验使用工具

> 提前声明三点：
> 1. 导入的 json 文件中的数据仅供参考，工具本身也不构成任何投资和财务决策，它只是提供计算结果和建议
> 2. 导入的 json 文件是安全的，因为 json 文件就是一个像 txt 一样的文本，你可以自己打开看，或者上网查，或者问 AI
> 3. 工具本身是安全的，这个工具是一个只在你本地(手机或者电脑)运行的应用，你的数据不会被上传到任何地方，一切都只有你自己知道，除非你主动导出一个 json 并发给别人

2. 尝试观察三阶段的内容

## 1 小时培训脚本（讲师版）

> 节奏建议：每个环节都“讲 1 句目的 → 做 1 个操作 → 看 1 个结果 → 提 1 个问题”。

### 0:00–0:05 开场：这工具解决什么问题

讲解要点（对小白）：

- 你不需要先懂理财术语，今天只做一件事：把未来几十年的“收入、支出、资产变化”用一张表和两个图讲清楚。
- 这个工具不只回答“能不能 FIRE”，更回答“稳不稳”“哪里最脆弱”“怎么改更合理”。

操作（讲师端）：

- 展示 App 首页，指出三阶段（Stage 1/2/3）。

### 0:05–0:12 三阶段速览（先让听众知道接下来要干什么）

一句话解释：

- **Stage 1**：把人生拆成几段，把收入/支出“写进规则里”。
- **Stage 2**：把规则生成成逐年的表格，允许你像 Excel 一样改其中的部分数字。为什么要改，因为有些列的值是一个特别的函数，比如我自己的保险支出，可能前几年是一个值，5 年后是另一个值，10 年后开始每年减少之类的，这种曲线在 Stage 1 没法直接表达，所以需要 Stage 2 来调整。
- **Stage 3**：把表格送进计算引擎，给你“可行性 + 风险 + 建议”。

提示听众：

- Stage 1 是“输入项”，Stage 2 是“调整表”，Stage 3 是“展示结果和建议”。

### 0:12–0:22 案例 S（失败示例）：为什么只看 4% 规则会误导

操作：

1. 导入 `fire-plan-demo-s.json`
2. 右下角一路下一步，直到看到结果，在每个阶段了解本页的内容

讲解要点：

- 这个计划里，“传统 4% 规则”会显示 **达标**，但 App 的“可持续性”会显示 **不可行**。
- 这正是今天要建立的直觉：**达标 ≠ 真的稳**。

参考结果（讲师备忘，1000 次模拟；不同机器会有小波动）：

- 目标 FIRE 年龄：45；当前年龄：31
- `traditional_fire_achieved = YES`（传统 4% 指标通过）
- `is_fire_achievable = NO`（本工具判定不可行）
- Monte Carlo 成功率约 `~6%`，Danger 约 `~93%`
- 末期净资产为负（约 `-130 万`），首次净资产 < 0 出现在约 75 岁附近

提问（让听众说一句自己的直觉）：

- “为什么 4% 通过了，但还是会失败？你猜失败发生在早年还是晚年？”

讲师解释模板（简短版）：

- 4% 规则本质是“一个粗糙的静态比值”，忽略了：桥接期、晚年支出结构变化、坏年份的连续性、以及你是否始终留得住安全垫。

### 0:22–0:40 案例 D（可调整示例）：把生活拆开看

操作：

1. 导入 `fire-plan-demo-d.json`
2. 停在 Stage 1，先不急着算结果

讲解要点（只讲“怎么填”，不讲金融课）：

1. **用户信息（Profile）**
   - 年龄从 `as_of_year - birth_year` 来
   - 目标 FIRE 年龄、法定退休年龄、预期寿命：决定你要覆盖多少年
2. **四个阶段（Phase 1–4）直觉**
   - Phase 1：现在到 FIRE（工作期）
   - Phase 2：FIRE+1 到法定退休（桥接期）
   - Phase 3：法定退休+1 到健康预期（退休期）
   - Phase 4：健康预期之后（晚年期）
3. **收入/支出条目（Items）**
   - 你不需要精确到每一笔；“把大项列出来”比“全部塞一个 Sum”更重要
   - `frequency = recurring` 表示每年/每月持续发生
   - `frequency = one-time` 表示只发生一次（例如一笔一次性支出/收入）
   - `interval_periods` 可以表达“每 N 年一次”（例如 10 年换车）

过渡句：

- “Stage 1 的目标不是算出一个答案，而是把你的生活写成一套‘规则’，让工具按规则生成未来每一年。”

### 0:40–0:48 Stage 2：表格与 Override（只讲一个动作）

操作演示（讲师端选一个最直观的例子）：

- 进入 Stage 2，找到某一年一个支出（例如装修/大件），把那一年金额改小（Override）
- 强调一句：**Override 是“某一年改一格”，不会改变 Stage 1 的规则本身**

问听众：

- “如果我只把某一年调小，这个影响会传递到后面每一年吗？为什么？”

### 0:48–0:58 Stage 3：怎么读结果（先读确定性，再读风险）

读结果顺序建议：

1. **可行/不可行（is_fire_achievable）**：先把“底线”看清楚
2. **净资产轨迹（Net worth over time）**：看“最低点”和“最危险的年龄段”
3. **Monte Carlo**：看“成功率”和 safe/warning/danger 分布

讲师备忘：案例 D 的基准结果（1000 次模拟）大致是：

- `is_fire_achievable = NO`
- Monte Carlo 成功率约 `0.1%`
- safe/warning/danger 约 `0.1% / 47.8% / 52.1%`
- 但确定性计算下，末期净资产仍为正（约 `213 万`）

这段要讲清一个核心点：

- “末期净资产为正”不代表稳；Monte Carlo 的 Danger/Warning 表示在大量随机情境里，你可能会在某些年份跌破安全阈值，甚至净资产转负。

### 0:58–1:00 关键演示：把案例 D 调成“可行且更稳”

今天最后 2 分钟只演示最有效的一招（对小白也最容易理解）：

**延长工作期、缩短退休期**（本质：多存几年、少花几年）。

操作（讲师端，按顺序做）：

1. 在 Profile 把“目标 FIRE 年龄”从 50 改到 **55**
2. 找到收入条目 Salary，把结束年龄从 50 改到 **55**（让收入规则与 FIRE 年龄同步）
3. （可选）如果有“FIRE 后才发生”的支出/社保，把开始年龄也顺延到 FIRE+1
4. 重新跑到 Stage 3 看结果

讲师备忘（500 次模拟的参考结果，便于你现场对照）：

- 基准：`achievable=false, mc≈0.4%`
- 改到 FIRE 55 并同步工资：`achievable=true, mc≈95.6%`
- 在上一步基础上，把所有经常性支出整体降 10%：`achievable=true, mc≈99.2%`

收尾句：

- “今天大家先记住：这个工具最擅长回答‘你差在哪一年、差在什么类型的支出/收入、以及最有效的改法是什么’。”

## 讲师备忘：常见问题（1 句话解释版）

1. **为什么传统 4% 通过了，但还是不可行？**
   因为 4% 是静态比值，而计划能否活到最后取决于“每年现金流 + 连续坏年份 + 安全垫 + 桥接期”等动态过程。

2. **Warning 和 Danger 到底差在哪？**
   Warning 是“没破产但紧绷”，Danger 是“出现净资产 < 0（破产/负债）”。

3. **Monte Carlo 成功率低是不是说明一定会失败？**
   不是“必然失败”，而是“在很多可能的未来里，失败概率很高”。它更像“天气预报”，用来做风险管理。

4. **怎么最快把成功率拉上去？**
   优先级通常是：延后 FIRE（多存/少花）→ 降低经常性支出 → 增加稳定收入（或减少大额周期性支出）。
